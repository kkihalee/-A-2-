## 프롬프트 원문 ② FAIL 고치기 (계획 승인 후 "진행")

```
'고치기 전에 정해주실 것' 1, 2번은 추천해주는 대로 진행

회귀 테스트의 FAIL을 고쳐 줘. 바로 고치지 말고 파일·함수별 수정 계획부터 보여 주고, 내가 승인하면 진행해.

지켜야 할 것
- 외부 AI API는 쓰지 않는다. 화면 수·화면 흐름·cards.json의 칸 key는 바꾸지 않는다.
- 문장 데이터·사전은 content.js(또는 cards.json), 로직은 engine.js에 둔다.
- 사용자가 입력하지 않은 내용을 칸에 채우지 않는다. 모르는 칸은 비워서 노란 칸으로 되묻는다.
- 시연 시나리오(재고평가충당금 → 선배 → 빈칸 보충 → 의도 체크 모두 ✓)가 깨지면 안 된다.
- 맞춤법·구어체를 고쳐도 의도 체크가 계속 ✓가 되도록, evidence는 고친 뒤의 본문에 글자 그대로 있는 구절로 만든다.

수정 방향 (박신화 님 제안, 더 나은 방법이 있으면 이유와 함께 제안)
1. splitByRules의 put(): 이미 찬 칸이면 버리지 말고 ', '로 이어 붙이기. DOING_RE에 '중인데|중이고|중이라|중이어서' 추가
2. META_RE로 조각을 통째로 지우지 말고 '~님께 여쭤보고 싶어요' 꼬리만 잘라내기
3. 시간 표현은 전부 찾아 마지막 것을 기한으로. 요청 인식에 '될지|되는지|해도|미뤄|연기|변경|받아야|해야|주셨으면' 추가,
   이유 인식에 '워서|와서' 추가. 일정 변경 요청은 기한을 요청 문장에서 빼지 않기
4. clauseValue(): '~와서→~옴', '~워서→~움', '~봐서→~봄' 규칙 + TONE_TABLE.memo에 맞는 변환 행 추가.
   칸 값이 여전히 연결어미(~서, ~고, ~는데, ~지만)로 끝나면 화면 2에서 노란 칸 + "문장 끝을 정리해 주세요(예: ~안 옴)" 안내
5. TONE_TABLE.memo의 '됨' 행: 판단 칸은 '된다고 생각합니다'(현재형), 사실 칸은 '됐습니다'
6. STRUCTURE_PRESETS.question에서 blocker 값 제거(지어낸 값 없애기)
7. 질문 카드에서 조각이 1개이고 '모르·막히·안 맞'이 있으면 blocker에 넣기
8. '더 부드럽게' 탭 전용 문장 틀(softSteps): 판단·질문 문장을 완곡하게
   (예: "제 생각에는 ~ 같은데, 혹시 제가 놓친 부분이 있을까요?", "~ 여쭤봐도 괜찮을까요?"). 칸 값은 그대로 유지

수정 방향 (유영채 님 피드백)
9. 맞춤법 교정 사전: 자주 틀리는 표현을 content.js에 표로 두고 메시지 만들 때 고친다.
   최소: 맞출려면→맞추려면, 할려면→하려면, 되요→돼요, 안되→안 되, 할께요→할게요, 몇일→며칠, 어떻해→어떻게,
   금새→금세, 왠만하면→웬만하면, 명사+' 되'(회신 되지·확인 되지·처리 되지·완료 되지)→붙여 쓰기
10. 구어체 순화 사전: 선배·인차지·클라이언트에게 보낼 때만 적용, 동기에게는 그대로.
   최소: 빡세다/빡세서→일정이 빠듯하다/빠듯해서, 근데→그런데, 걍→그냥, 진짜·완전(강조)→매우 또는 삭제,
   멘붕→어려움, 애매해요→판단이 어렵습니다, 땡기다→앞당기다, ~같아요(추측 남발)→~것으로 보입니다
   사전으로 바꾼 표현이 있으면 수정 이유에 "'빡세서'를 '일정이 빠듯해서'로 다듬었어요"처럼 1줄 추가(학습 효과).
11. 선택지 정리: 여러 줄·쉼표·①②·'또는'으로 나뉜 선택지를 항목으로 나누고, 끝 마침표를 지운 뒤
   "선택지는 ① 회신 재요청, ② 3건 대체적 절차 진행 두 가지입니다."처럼 한 문장으로 넣는다(문체 설정에 맞게).
   항목 문장 끝의 '진입.' 같은 메모체도 자연스럽게(진행) 바꾼다.
12. 인차지에게 보낼 때 첫 줄에 용건을 먼저 밝힌다(예: "[묻고 싶은 것] 관련해 여쭤볼 게 있습니다."). 나머지 순서는 유지.
    수정 이유에 "인차지님께는 용건을 먼저 밝혔어요" 표시.

다 고친 뒤 회귀 테스트를 다시 돌려 수정 전/후 PASS 수를 비교하고, 새로 깨진 케이스가 있으면 알려 줘.
샘플 30건 전체도 돌려서 비문·문체 혼합이 0건인지 확인해 줘.
```
